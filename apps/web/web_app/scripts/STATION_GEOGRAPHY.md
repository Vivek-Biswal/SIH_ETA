# Station geography used by the journey map

`public/station-geography.json` is generated by `python scripts/build-station-geography.py`
from the existing repository file `railway_eta_data/data/processed/stations_clean.json`.
The source is the project's historical Indian Railways station directory (the raw
dataset README credits Sanjay and Sajjad / geohacker). It is not live location data.

Only KEEP records with finite coordinates are exported. Conflicting station codes
are excluded. Provider-supplied station coordinates take precedence. The browser
loads this compact directory once and caches it; missing stations use at most four
concurrent API lookups. Successful lookups last 24 hours in a bounded memory cache;
failed or missing lookups wait five minutes before retrying.

Route order always comes from the selected train's status response. Repeated visits
are preserved, missing geography creates a visible gap, and dashed segments are
approximate station connections, not surveyed track geometry. The position marker
uses reported coordinates, or an unambiguous last reported station. The 1.5-second
transition between fresh coordinate observations is visual smoothing, not a new
position measurement or extrapolation. Old observations do not animate.

The map and arrival panel share one status/ETA load per polling cycle. Polling stops
while hidden and backs off to up to four minutes after errors. Historical insights
are refreshed on demand rather than polled.
